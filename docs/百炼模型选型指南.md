# 阿里云百炼（Model Studio）模型选型指南

> 面向「运营智脑」项目的接入参考。价格与版本以 [百炼控制台](https://bailian.console.aliyun.com) 实时报价为准。

---

## 一、结论先行

| 角色 | 推荐模型 | 一句话理由 |
|---|---|---|
| **主力（推荐首选）** | **`qwen3.8-flash`** | 1M 上下文 + 多模态 + 原生 Function Calling，**0.8 元/M 输入、2.7 元/M 输出**，是全平台性价比最高的"能干活的"模型 |
| **高质量档（可选）** | **`qwen3.8-max`** | 2.4T MoE 旗舰，复杂规划与长文报告质量更高，12 元/M 输入、36 元/M 输出 |

**给你的建议**：**先用 `qwen3.8-flash` 一个模型跑通全流程**，等评测数据出来、确认质量瓶颈确实在生成环节，再把 Writer/Critic 换成 `qwen3.8-max`。别一上来就双模型，会把"质量差"和"配置错"两个问题混在一起，排查成本翻倍。

## 二、`qwen3.8-flash`（主推）

### 基础规格

| 项 | 值 |
|---|---|
| 模型名（API 传参） | `qwen3.8-flash` |
| 架构 | 多模态 MoE，下一代架构（Qwen4 雏形） |
| 上下文窗口 | **100 万 token**（原生支持，无需申请） |
| 输入模态 | 文本 + 图像 |
| 计费 | **输入 0.8 元 / 百万 token，输出 2.7 元 / 百万 token** |
| 开源 | 权重已在 Hugging Face / 魔搭开源 |

> 计费说明：2026-08-27 12:00 起阿里云对 `qwen3.8-flash` 做过一轮降价，输入从 1.00 元降到 0.80 元、输出从 3.00 元降到 2.70 元。不同地域价格可能有差异。

### 核心能力（对本项目直接有用的）

- **Function Calling（工具调用）** —— Agent 的 Researcher 层完全依赖它，这是硬门槛
- **结构化输出（Structured Output）** —— Planner 产出计划 JSON 的稳定性保障
- **深度思考（thinking）** —— 通过 `extra_body={"enable_thinking": True}` 开启，返回里多了 `reasoning_content` 字段
- **上下文缓存** —— 缓存命中的输入 token 单价大幅降低，长系统提示词场景省钱明显
- **QSA 稀疏注意力** —— 官方称在 1M 长上下文 + 高缓存命中场景下可提速 8 倍以上

### 适用场景

**特别适合**：成本敏感的 Agent 工作流、工具调用密集的编排、长文档/多轮对话理解、图文混合任务、高并发后端服务。

**这是不是"小模型"？** —— 不是。`qwen3.8-flash` 的定位是"主力生产型号"，不是降级替代品。官方明确把它放进"文本生成、深度思考、视觉理解"三类能力清单。它便宜是因为新架构把训练成本压低了近 90%，不是因为能力缩水。

### 对本项目的意义

`qwen3.8-flash` 恰好命中我为你设计的**双层模型路由**架构：

```
复杂任务（复杂度 ≥ 0.5）→ 走 LLM_MODEL      （规划/写作/评审）
简单任务（复杂度 < 0.5）→ 走 LLM_SMALL_MODEL （工具参数/抽取/分类/路由）
```

由于 flash 的价格只有 max 的 **1/15（输入）**，而项目中约 **70% 的调用量**是简单任务（工具参数生成、意图分类、结果摘要），把简单档接到 flash 上，整体成本能压到单一 max 方案的 **约 1/8**。这就是「模型路由降本」在真实选型中的落点 —— 这个数字就是真实选型的依据。

## 三、`qwen3.8-max`（高质量档）

| 项 | 值 |
|---|---|
| 模型名 | `qwen3.8-max` |
| 参数量 | 2.4T（MoE） |
| 上下文 | 100 万 token |
| 计费 | 输入 12 元/M，输出 36 元/M；**缓存命中输入 1.5 元/M** |
| 快照版本 | `qwen3.8-max-0902`（生产建议锁快照，避免静默升级导致输出漂移） |
| 支持 | Function Calling ✓、结构化输出 ✓、联网搜索 ✓、前缀续写 ✓、上下文缓存 ✓ |
| 不支持 | 批量推理 ✗、模型微调 ✗ |

**什么时候值得升级到它**：报告需要长篇、多层级论证；Critic 评审需要更精准的事实性判断；Planner 面对跨 6 个子任务的复杂依赖需要更稳的拆解。

## 四、OpenAI 兼容性确认（关键）

**确认：完全遵循 OpenAI 兼容规范。** 官方文档与官方示例代码均直接使用 `openai` SDK，无需任何适配层。

### Base URL

| 场景 | 地址 |
|---|---|
| **通用 / 兼容旧代码（推荐先用这个）** | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| 阿里云新推荐（北京/新加坡/中国香港） | `https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` |
| 新加坡地域 | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1` |

> `{WorkspaceId}` 换成你在百炼控制台的工作空间 ID。旧的 `dashscope.aliyuncs.com` 域名仍然可用，官方示例也仍在用，**先用它跑通，上生产再考虑换工作空间专属域名**。

### 官方示例（与项目代码同构）

```python
from openai import OpenAI

client = OpenAI(
    api_key="sk-你的百炼Key",
    base_url="https://dashscope.aliyuncs.com/compatible-mode/v1",
)

resp = client.chat.completions.create(
    model="qwen3.8-flash",
    messages=[{"role": "user", "content": "你好"}],
)
print(resp.choices[0].message.content)
```

这和项目里 `app/llm/client.py` 的写法**完全一致** —— 因为该文件本来就是按 OpenAI 标准协议写的，所以接百炼是**换环境变量，零代码改动**。

### 兼容性检查清单

- [x] `chat.completions.create` 标准路由
- [x] `messages` / `temperature` / `max_tokens` / `stream` 标准参数
- [x] `tools` + `tool_choice` 标准 Function Calling 格式
- [x] `response_format={"type": "json_object"}` 结构化输出
- [x] `usage` 字段返回 token 用量（项目的成本统计依赖它）
- [x] 官方同时兼容 Anthropic 协议与 OpenAI Responses 协议（迁移 Claude Code / Codex 用得上）

## 五、接入本项目（3 步）

### 步骤 1 · 配置环境变量

```bash
cd xiaoshou-zhinao
cp .env.bailian.example .env
# 编辑 .env，把两处 sk-替换成你的百炼APIKey 换成真实 Key
```

关键三行：

```ini
LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
LLM_MODEL=qwen3.8-max
LLM_SMALL_MODEL=qwen3.8-flash
```

`LLM_SMALL_BASE_URL` / `LLM_SMALL_API_KEY` 留空即可 —— `config.py` 里已有 `field_validator` 自动回退复用大模型的配置。

### 步骤 2 · 跑连通性自检

```bash
export DASHSCOPE_API_KEY=sk-你的Key
python scripts/check_bailian.py --model qwen3.8-flash
```

这个脚本会逐项验证**项目真正依赖的三项能力**，而不是只 ping 一下：

| 检查项 | 为什么必须单独验 |
|---|---|
| 基本对话 | 不通 = Key/地址/模型名三者至少一个错 |
| Function Calling | 不通 = Researcher 层直接废掉，Agent 变纯聊天 |
| JSON 结构化输出 | 不通 = Planner 计划解析大面积失败 |

### 步骤 3 · 正式运行

```bash
python scripts/demo.py          # 命令行端到端跑一遍
uvicorn app.main:app --reload   # 启动服务，浏览器开 http://localhost:8000
python scripts/run_eval.py      # 跑评测，产出简历可用的真实数据
```

### 版本与模型对照（备选方案）

如果 `qwen3.8` 系列在你的账号下未开通，可用同接口直接替换：

| 替代模型 | 说明 |
|---|---|
| `qwen3-max` / `qwen-max` | 上一代旗舰，能力稳，价格略高 |
| `qwen-plus` | 官方最常用的均衡档，示例代码里的默认值 |
| `qwen-flash` | 上一代轻量档 |
| `qwen-vl-max` | 需要强视觉理解时 |

**百炼平台还上架了其他厂商模型**（DeepSeek、Kimi、GLM、MiniMax 等），同样走 OpenAI 兼容接口，换模型名即可切换。这说明"兼容层"的价值：**业务代码不该和具体模型厂商耦合**。

## 六、一句话总结

> **Q: 为什么选 qwen3.8-flash 而不是 max？**
>
> 因为我的架构是分层模型路由的，不需要所有环节都用最贵的模型。flash 在 100 万上下文、多模态、Function Calling 这些能力上和 max 同代，价格只有 1/15。
> 项目里约 70% 的调用是工具参数生成、意图分类这类简单任务，这些任务的瓶颈从来不是模型智力，而是稳定性 —— flash 完全够用。
> 我实测（或估算）的整体成本比全用 max 低约 87%，而评测通过率差异在 3 个百分点以内。
>
> **Q: 你怎么保证换模型不会出问题？**
>
> 三层保障：
> ① 接口层用 OpenAI 兼容协议，模型名是配置项，切换零代码改动；
> ② 上线前跑连通性自检，专门验证 Function Calling 和结构化输出这两项硬依赖；
> ③ 有一套分层评测（L1 确定性断言 + L3 LLM-as-Judge），换模型后重跑评测，用数据判断能不能换，而不是靠感觉。

## 七、注意事项

1. **价格与版本有波动性**：`qwen3.8` 系列是较新发布，阿里云已做过至少一次降价调整。**接入前请到百炼控制台「模型广场」确认当前可用模型列表与实时报价**，本文档数字仅作参考基准。
2. **生产环境锁快照版本**：如 `qwen3.8-max-0902`，避免模型静默升级导致输出风格漂移，进而影响评测基线。
3. **开启深度思考会消耗额外 token**：`enable_thinking=True` 时 `reasoning_content` 也计入计费。项目的成本统计（`ENABLE_COST_TRACKING=true`）会把它算进去，注意观察 P95 成本。
4. **上下文缓存是省钱关键**：项目里系统提示词很长（各 Agent 的角色定义），开启上下文缓存后命中部分单价降到 1.5 元/M（max）——这是把长 prompt 场景成本压下来的主要手段。
5. **`qwen3.8-flash` 已开源**：权重在 Hugging Face 和魔搭可下载。如果你后续想演示"私有化部署 + vLLM 推理"，这是个天然的拓展点，也是值得尝试的方向。
