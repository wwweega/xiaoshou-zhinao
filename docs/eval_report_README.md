# 关于评测报告

`eval_report.md` 由 `python -m scripts.run_eval` 生成。

## 两种模式的差异（重要）

| 模式 | 命令 | 通过率表现 | 说明 |
|---|---|---|---|
| **Mock 模式** | `LLM_PROVIDER=mock python -m scripts.run_eval` | 偏低（约 40-60%） | LLM 返回固定占位文本，不含业务关键词，**「关键词命中率」必然失败**。这不是缺陷，是评测在正确工作 |
| **真实模型** | 配好 `.env` 后 `python -m scripts.run_eval` | 反映真实效果 | 这才是你要写进简历的数据 |

## 简历要用的数据怎么拿

```bash
# 1. 配 .env（填 Key）
# 2. 跑全量评测（建议 20 条都跑，约 20-40 分钟取决于模型速度）
python -m scripts.run_eval

# 3. 打开 docs/eval_report.md，把这些数字填进 README 的「实测数据」表：
#    - 用例总数 / 通过数 / 通过率
#    - L1、L2、L3 各层通过率
#    - 单任务平均 token、平均耗时
```

## 面试时怎么讲这份报告

> 「我建了三层评测。L1 是确定性断言，快且免费，能进 CI；
> L2 是针对 Agent 系统特有的行为指标，比如子任务完成率、反思有效性；
> L3 是 LLM 裁判，只做抽样，因为它有偏差。
> 我用 mock 模式验证过评测管线的正确性——mock 下通过率明显偏低，
> 因为固定文本不含业务关键词，这恰好证明评测确实能检测出内容缺失。
> 真实模型下 20 条用例的通过率是 XX%。」

**关键**：主动说出 mock 模式通过率低的原因，展示你理解评测的每一层在测什么，
而不是拿一个漂亮的数字糊弄。
